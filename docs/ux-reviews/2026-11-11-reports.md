# UX review — Hand in a progress report (plan 14.1–14.2), 2026-11-11

Cognitive walkthrough + Nielsen heuristics, read from source (ux-reviewer, inline), on the screens ported from PLC+:
`Learning/ReportScreens.cs`, `Learning/CoursePage.cs` (the report page and its buttons, the Course help),
`Learning/DashboardPage.cs`, `MainWindow.xaml` / `MainWindow.Course.cs` (menus), `Learning/LearnerScreen.xaml`,
`Learning/ExerciseEvidence.cs`, and the PDF renderer in Learning Core.

Tasks walked: a student hands in a first report; a student not signed in tries; an instructor makes a class code and
checks a PDF and a STAT1 line; a student makes an incomplete report.

**0 Critical, 2 Major, 7 Minor. All fixed except where noted.**

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | Major | "Report" meant both the Workbench's analysis PDF (File ▸ Save report as PDF) and the signed progress report; a student could hand in the unsigned one | "Progress report" everywhere a person reads it: Learner ▸ Hand in a progress report…, Save the progress report (PDF)…; the Workbench's report tooltips and the report page say which is which; the verifier's "not signed" verdict names the Workbench report |
| 2 | Major | PLC+'s words printed on every PDF: "tests", "a hidden test", "Submission point", "pass/FAIL", "the lab or a proctored challenge" (in a statistics course a test is a hypothesis test) | Learning Core 1.2.0 takes these from the program; Statistics+ prints "Module check", "Answers checked, from the best attempt", right/WRONG, "use a proctored exam" |
| 3 | Minor | Access keys used twice in My details for reports (E, C, S) | Sec_tion, C_ontinue, Save my _details |
| 4 | Minor | Access keys clashing with the main menu (_File, _Project, _Help) | Show the file in its f_older; Hand in a progress rep_ort…; Chec_k … on the start screen as in the menu |
| 5 | Minor | "Everything so far — … every module written so far" (author's words), and the full report warned "not complete" before saving | "Everything so far — every module, with what you have done and what is left"; its card says a full report is Incomplete until the course is done; no warning before making it |
| 6 | Minor | The Course help said nothing on My details, the class code, Incomplete, not re-saving the PDF, or where instructors check | The help's "Handing in your work" says each, and points instructors to File ▸ Check reports and class codes. F1 on the report page still opens the general help (Back goes to My progress): kept, as everywhere in the Course |
| 7 | Minor | Making a class code was hidden behind "Check a report" | Renamed **Check reports and class codes (for instructors)…** (File menu, start screen, window title); its intro says to make a code at the start of term. The new code is not put in the check box: kept, on purpose (the box is for the code being checked) |
| 8 | Minor | The PDF's how-to-check line says "File, then …" where the program writes "File ▸ …" | Kept: the PDF's font set is small, and "then" reads the same aloud |
| 9 | Minor | Send to my instructor with no result line wrote an empty "Result line:" | The e-mail leaves the block out |

Still to look at by eye (Ron's hand-test, part V): the status line after saving, a long "Still to do" list on the card,
the verifier's capitalized verdicts with Narrator, the details dialog at 560 px, and the evidence picture at 440 pt in the PDF.
