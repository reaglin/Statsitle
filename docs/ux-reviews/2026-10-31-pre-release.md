# Statistle — pre-release UX review, 2026-10-31

Saved verbatim as received (2 Critical, 7 Major, 9 Minor). What was done with each finding is in
`docs/DEVELOPMENT-PLAN.md`, phase 6.

REVIEW (2 Critical, 7 Major, 9 Minor):
C1. Closing, New, Open and the Store update throw away unsaved work without asking. MainWindow.xaml.cs:406 Exit_Click => Close() with no OnClosing; WorkspaceViewModel.cs:903-929 New/Open never check IsDirty; StoreUpdates.cs:63 says "Your work is kept…" but nothing is saved; the LocalAppData autosave (:878) is never offered back. Fix: one ConfirmDiscard() used in New, Open, Closing and before the Store install ("Save changes to {file} before closing? Yes saves, No discards them, Cancel goes back."); optionally on start "Statistle closed with unsaved work. Restore it?"
C2. Undo after New/Open restores the old project and can overwrite the file just opened: _undo never cleared (:789-816); Undo() calls Document.SetFilePath(path) with the new path (:832). Fix: clear undo + RaiseCanExecuteChanged in NewProject() and after a successful OpenPath().
M3. Typed value not saved by Ctrl+S / File ▸ Save and Enter does nothing: boxes update on LostFocus (MainWindow.xaml:204,260,325). Fix: commit the focused TextBox binding at the start of Save, CopyCode, ExportPdf…; Enter commits in ValueBox.
M4. Rejected entry gives no reason; results keep the old value (PropertyRow.Reject() :698 only reds the box; table paste rejected whole). Fix: error text under the box and in the help panel: "'{text}' is not a number, so Statistle is still using {old}. Correct it or press Esc."; tables: "Line {n}, column '{name}': '{cell}' is not a number. The paste was not used; your earlier data is kept."
M5. Open/Save failures only in the status bar (OpenPath :686, Save :962); OpenPath misses XmlException/UnauthorizedAccessException → crash. Fix: MessageBox "Statistle could not save to {file}: {reason}. Try Save As… to a folder in Documents."; catch both.
M6. First run opens blank; the sample demo-statistics.statistle (App.xaml.cs:50) is never mentioned. Fix: File ▸ Open the sample project, and the empty-state help: "New here? … Or click + Data table to enter your own numbers, then pick an analysis on the left."
M7. "Choose the data table." dead end with no tables (OneWayAnova.cs:530, TwoWayAnova.cs:398, MultipleRegression.cs:375, ConfidenceInterval.cs:440 + test analyses). Fix: when Document.Tables is empty: "This analysis reads a data table, and the project has none yet. Click + Data table on the left, paste or Import your data, then come back and choose it here."
M8. Analyses not in the Project tree; Delete selected on an analysis silently does nothing but pushes undo (:982-993). Fix: disable Delete for analyses with tooltip "Analyses are opened from the list on the left; only data tables can be deleted." (or list them); highlight the active rail button.
M9. Import… on a table replaces every column with no preview and silently takes sheet 1 (MainWindow.xaml.cs:279-288). Fix: reuse ImportDialog with sheet choice; status "Imported {n} columns from {file}, sheet '{sheet}'. Ctrl+Z puts the old data back."
Minors to take: Report tab text (:596) → "…and the sources of its methods. Save it as PDF for your report."; Code tab (:634) → "check that it prints the same numbers as the Properties tab."; "Export selected artifact…" → "Export selected item as XML (advanced)…"; proper singular/plural (:682); confirm table delete and name the table not its id (DataTable.cs:185); series import status "Imported {n} values from {file}."; consistent names "Save as PDF…" everywhere. Do NOT change the privacy wording (plan 5.7 is Ron's decision) — leave it ⚠️.
